## How the agent steps were run

Part A drives the real app from a terminal. Nothing in it needs an eye or a hand on native UI.

- The app is the debug build, started with `DOTS_DATA_DIR` set to a fresh folder under `mktemp -d`. The real data folder `%LOCALAPPDATA%\dots` is never used. The webview's own profile is moved too (`WEBVIEW2_USER_DATA_FOLDER`), so `%LOCALAPPDATA%\dev.dots.app` is not touched and a second instance can have its own debugging port.
- The Claude dot runs the fake CLI (`fake-claude.exe`, copied out of `target/`), set through the `claude_path` setting. `DOTS_CONFIRM=yes` answers the native confirmation in a debug build. The app is started with a `PATH` that has no folder with the real `claude` in it, so Dots never starts the real CLI, not even for `--version`.
- `FAKE_CLAUDE_SCRIPT` names one file, `$SMOKE/script.json`. The fake CLI reads it when a run starts, so a step copies the script it wants over that file first (`use_script`).
- The window is driven through WebView2's debugging port with `tools/smoke/webview.mjs`: `click`, `dblclick` and `fill` act on a control by its accessible name, with the mouse and text events a person makes; `eval` calls a command through the Tauri bridge; `text` and `shot` read the page.
- Every block is run in Git Bash from the repository root. Shell variables do not have to survive from one block to the next: block A2 writes a state file, and every later block starts by reading it (`. "${E:?}"`, where `E` is that file's path, `$SHOTS/env.sh`). A shell that forgets variables sets `E` again before each block.
- Git Bash rewrites an argument that starts with `/` into a Windows path, also inside a quoted JavaScript expression (`split("/")` does not arrive as written). The blocks avoid such arguments: `taskkill //PID`, routes without the leading slash, `slice(-26)` for the id at the end of an address.
- Safety: block A1 says "STOP" when a `dots-app.exe` or `fake-claude.exe` is already running; then nothing more is run, and nothing is stopped. Only processes these blocks started are stopped, by their process ids. The installer and the real `claude` CLI are not run.
